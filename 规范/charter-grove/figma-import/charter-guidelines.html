CHARTER DESIGN SYSTEM

设计基础与规范

这是供设计、开发和 Figma 对照使用的基础页。颜色、字号、间距、圆角都直接来自同一份 token 源。

浅色 / 深色83 个变量

核心原则

友好的外壳，严谨的内容

标题可以亲切；字段、日期、状态和法律术语必须准确。

一眼知道情况

先给状态横幅，再给数字，再给明细。

下一步永远清楚

每条坏消息都跟一个明确可点的下一步。

立体感 = 可以按

只有按钮和结构图节点使用 4px 立体底边，信息卡片保持平。

值得庆祝的才庆祝

完成申报、补齐档案时给一点小奖励；日常浏览保持安静。

每个结论都有出处

字段旁标注来源和核对人，识别信息能回到原文件。

组件目录

Icon基础

线性图标：24 网格、2px 描边、圆角端点，与初稿使用的 Lucide 风格一致。

Button操作

立体按钮：底部 4px 深色边，按下时整块下沉 4px、底边消失，松开时回弹一下。这是整套设计最有辨识度的元素。

Avatar基础

头像与徽章：浅色底 + 同色系深色字。

StatusPill状态

状态胶囊：小圆点（或图标）+ 文字 + 浅色底，圆角 8px。颜色只是加强，去掉颜色也能读懂。

Sidebar导航

侧栏：224px 白底，右侧 2px 描边。从上到下：标志、集团切换、主导航、工作区导航、安心提示卡、当前用户。

AppBar导航

顶栏：72px 白底，底部 1px 描边。左侧是当前集团和位置，右侧是同步状态、今天日期、提醒、帮助。

PageHeading导航

页面标题：面包屑（12/600 灰）→ 大标题（Nunito 900 32px）+ 操作按钮 → 一行副标题（14 灰）。

HealthBanner数据

状态横幅：每页最多一个，放在页面标题下方，用一句话回答“现在情况怎么样”。

ProgressSegments数据

进度段：一段代表一个对象（一家公司、一项档案），按状态着色。

MetricTile数据

数字卡：大数字（Nunito 900 29px）+ 图标 + 名称 + 一句补充说明。总览页一排四个。

SearchField输入

搜索框：40px 高、10px 圆角、2px 描边，左侧放大镜。聚焦时描边变品牌绿并加 3px 浅绿光圈。

Field输入

表单字段：标签（11/700 灰）在上，输入框在下，说明或错误在最下。

ViewToggle输入

显示方式切换：列表 / 卡片。选中项浅绿底绿色图标，未选中只有灰色图标。

Tabs导航

页签：底部 2px 灰线，选中项绿字 + 4px 绿色下划线。

Card布局

卡片：白底、2px line 描边、20px 圆角、24px 内边距，没有阴影。

EntityTable数据

公司表：总览页的主体。列：公司（徽章 + 名称 + 编号与形式）、法域（地区 + 登记机关）、合规、下一件事（日期 + 事项）、负责中介、进入箭头。

EntitySnapshot数据

公司概况条：公司页面标题下方，一行回答四个问题——登记状态、合规、档案完整度、默认中介。

FactGrid数据

字段网格：两列，每格是标签 + 值 + 一行补充说明。上方一行写数据来源和核对人、核对日期，这是专业信任感的来源（初稿里的「UK registry record · Reviewed by …」）。

PeopleTable数据

人员与持股：三列——人员、职务、持股。

DocumentList数据

文件列表：概览页里的精简版文件清单，只放最重要的 3–5 份。完整的文件表在「文件」页签。

NextUpCard数据

下一件事：公司页右栏的第一张卡，琥珀底 + 琥珀描边，告诉用户这家公司最近要做的一件事。

HorizonList数据

远期事项：“下一件事”之后的两三件，日期绿色加粗在上，事项名在中，机关与表格编号在下。

AuditNote反馈

变更记录说明：放在右栏底部，告诉用户每次改动都有记录、可以撤销。只是说明，不是卡片。

InfoNote反馈

提示卡：蓝色底，用于消除顾虑的说明（离线、隐私、数据位置）。标题亲切，正文写清实际行为。

DeviceRow数据

设备行：设备图标块、名称 + 状态胶囊、系统与版本、同步情况、更多操作。

Toggle输入

开关：44×26，打开为品牌绿。圆点滑动带一点回弹（200ms）。

ChoiceCard输入

选择卡片：一组单选，每个选项是一张卡片。用于同步冲突、识别结果二选一等“请你来定”的场景。

ActivityList数据

动态列表：图标 + 一句话 + 时间。绿色双勾表示完成，琥珀图标表示需要注意。

StructureChart数据

股权结构图：节点是带 4px 底边的立体卡片，和按钮同一种语言；点阵背景。

FilingTimeline数据

申报日历：按月分组，每行是日期与剩余天数、事项、公司与机关、状态、完成圆圈。

Celebration反馈

庆祝时刻：只在完成一个有意义的阶段时出现——本月申报全部办完、一家公司档案补齐到 100%、第一次导入完成。

DropZone输入

拖放区：2px 虚线框、浅灰底。拖入时变为品牌绿虚线 + 浅绿底。整个公司页面都接受拖放。

UploadRow输入

上传行：文件名 + 真实进度条（品牌绿）→ 完成后换成识别出的类型和一句摘要。多份识别完后出现蓝色汇总框（上浮淡入 200ms），每一项都能点回原文件。识别失败时在行内写原因和下一步。

ProcessSteps反馈

处理步骤：几秒钟的后台任务拆成看得见的几步。每步真正完成时才打勾（对勾弹出），当前步转圈，完成的步右侧写结果。少于 1 秒的任务不显示。

EmptyState反馈

空状态：浅绿图标块 + 标题（说清缺什么）+ 一句话（这类信息通常在哪份文件里）+ 一个主按钮。不写「暂无数据」。

Toast反馈

轻提示：底部居中，墨色圆角块，左侧绿色对勾圆。

Dialog反馈

弹窗：24px 圆角、28px 内边距，弹入（320ms 回弹）。只用于不可逆操作的确认和 4 个字段以内的短表单。

实现说明

描边：统一 2px。颜色 line 只做分隔，line-strong 用于输入框和交互控件边界。

立体边：按钮 4px，徽标 6px；按下时元素下沉、底边归零。普通卡片不用阴影。

布局：侧栏 224px，顶栏 72px，页面边距 32px；区块间距 24px，卡片间距 20px。

日期：绝对日期使用 YYYY-MM-DD；相对时间写“还有 28 天”“逾期 3 天”。
